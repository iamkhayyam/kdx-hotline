# KDX Build Evaluation — 2026-08-17

Evaluation of the `kdx-hotline` workspace: build health, test suite, code and
security review, plus a live end-to-end smoke test. Performed with Rust
1.94.0 (stable, aarch64-apple-darwin).

## Verdict

**Pass.** The workspace builds with zero warnings, all tests pass, clippy is
clean, and the full stack — TLS handshake, TOFU pinning, challenge-response
login, chat, file listing, live presence events — works end-to-end against a
real running server.

Test inventory: 225 unit tests, 13 integration tests (real servers over live

`transfer` in `crates/kdxd/tests/`, plus `tofu`/`transfer` in

The smoke run (`crates/kdx-client-core/examples/smoke.rs`) against a fresh
server with a temp DB exercised: `kdxd useradd` → server start (self-signed
cert generated + cached) → client connect → TOFU pin of the SPKI fingerprint
→ challenge-response login (class 2 = power) → join `#lobby` → send chat →
list `/` → receive a live `UserList` push event. The one `HandshakeFailure`
warning in the server log is the smoke client's own first (untrusted) contact
before pinning — expected behavior.

## 2. Security review

No defects found. Notable strengths:

- **Auth** — Argon2id at rest; challenge-response login
  (`SHA-256(challenge ‖ verifier)`) so the password never crosses the wire;
  constant-time comparison; `Zeroizing` on the verifier; decoy challenges for
  unknown usernames (anti-enumeration); 3-attempt cap; session TTL.
- **Transport** — TLS 1.3 (rustls); client TOFU-pins the server SPKI per
  `host:port`; server caches its dev cert so restarts keep identity.
- **DoS guards** — frame payload cap enforced before buffering; reassembly
  cap (4 MiB) + 30 s group timeout; outbound queue cap with drop-not-stall;
  per-member chat token-bucket flood gate; search/history result caps.
- **Paths** — uploads stored under server-generated UUID names, never
  user-controlled paths; alias ACLs resolve through the target's parent
  (the alias-ACL-bypass case is explicitly handled).
- **Storage** — no dynamic-SQL patterns; versioned migrations; WAL +
  `foreign_keys(true)`.
- **Config** — `deny_unknown_fields`; dev self-signed cert only when no TLS
  config is supplied.

## 3. Code quality

- Zero TODO/FIXME/`unimplemented!` markers in ~21k lines of Rust.
- Clean crate layering: protocol → crypto → storage → server-core →
  client-core → daemon/UI. `connection.rs` (2.5k lines) is the largest file
  but reads as a clear state machine.
- Tests are behavioral (round-trips, partial reads, oversized frames,
  corrupted headers, paused-time flood gates) rather than tautological.

Minor observations (non-blocking):

- `spki_fingerprint()` in `crates/kdx-client-core/src/tls.rs` hashes the
  whole leaf cert DER despite the name — fine for TOFU, worth renaming or
  re-commenting.
- `KnownHosts` hand-parses its TOML file; safe for the current key format
  (base64 fingerprints) but a real `toml` dep would be more robust.
- 48 Tauri commands exposed to the webview — fine under the current CSP,
  worth watching as the surface grows.

## 6. Multi-window refactor (floating desktop windows)

Per the design correction — every KDX window must float freely on the
desktop and minimize to the OS Dock — the client moved from a single-window
app with an in-webview window manager to a true multi-window Tauri app:

- **Launcher window** ("main", 208×540, undecorated) hosts the Button Bar;
  closing it quits the app, minimizing sends it to the Dock.
- **18 feature windows** (Connect, Chat, Files, Transfers, Address Book,
  Settings, About, User List, User Info, Messages, Administration, Accounts,
  Server, Server History, IP Rules, Connections, Public News, Trackers) are
  created at runtime via `new WebviewWindow(label, { url: "index.html?win=" +
  label, ... })` — each is a real macOS window with the classic red titlebar
  (custom-drawn, `decorations: false`, `data-tauri-drag-region` for native
  dragging, real minimize/maximize/close wired to native APIs).
- **Per-window entry**: `main.js` dispatches on the `?win=` param;
  `windows/registry.js` holds each window's config + event slices.
- **Cross-window channel**: server events ("kdx") are already broadcast to
  all windows by the Rust forwarder (`AppHandle::emit`); window-to-window UI
  commands ride a new "kdx-ui" event channel (`{to, action, ...}`) —
  "session"/"login-success" broadcasts from Connect, "open-with"/"show"/
  "open-disconnect"/"fill"/"submit" verbs, and window-opened/window-closed
  announcements keep the launcher's buttons in sync.
- **Capabilities**: `capabilities/default.json` now covers every window label
  and grants the window/webview permissions the new APIs need
  (`core:webview:allow-create-webview-window`, `core:window:allow-close`,
  `-minimize`, `-unminimize`, `-toggle-maximize`, `-set-focus`, `-show`,
  `-set-always-on-top`, `-set-position`, `-start-dragging`, ...).
- **Geometry**: saved per window in localStorage (shared origin), sanitized
  on load (corrupt / off-scale values rejected) and only persisted for
  non-maximized windows in logical pixels.
- **Preview mode** (no Tauri): windows stack in-page so the UI can still be
  iterated in a plain browser.

Verified live: two launch passes with a CoreGraphics window probe showed the
launcher (208×540) and Connect (300×320 at 200,33) on screen with correct
sizes, zero webview errors, and sane behavior across restarts. Two bugs were
found and fixed during verification: (1) `WebviewWindow.getByLabel` returns a
lazy handle even for never-created labels, so existence must be checked via
`getAll()` — without this the Connect window was never created; (2) persisted
geometry could carry off-scale physical sizes (once a 3420×2148 window) —
now sanitized on load and capped on save.

**Doc follow-up**: `docs/handoff.html` still describes the old in-webview
window manager and is now stale on that section.

## 7. Polish pass (late-night, pre-test)

Refinements after the multi-window refactor, all verified against a live run:

- **Resize everything**: every feature window is resizable (the `resizable:
  false` on Connect/Settings/About/User Info is gone) with a per-window
  minimum size so content never collapses (e.g. Connect 260×320, Chat
  480×260, Files 360×240). Sizes/positions persist per window in logical
  pixels.
- **Resize grip**: classic Mac-style double-triangle in the bottom-right
  corner (blood-red, brightens when focused). Pointer-transparent — the
  native edge-drag does the resizing.
- **Focus glow**: restored the classic "focused window lights up" behavior —
  the focused window gets the bright titlebar gradient, red border, and hot
  grip (via `onFocusChanged` + `isFocused`; added `core:window:allow-is-focused`).
  The launcher strip glows too.
- **Window menu**: the titlebar menu button and right-click now share one
  state-aware menu — Keep on Top toggles with a ✓ check, Maximize/Restore
  reflects the current state, Save Location/Size persists, then Minimize/Close.
- **Dead CSS removed**: the old in-webview `.menubar`, `.dock`/Dock-window,
  `.win.hidden/.maximized/.pinned` rules are gone (native windows own those
  behaviors now).
- **README**: the client section now describes the launcher + floating
  multi-window model.

Two bugs fixed during verification (both Tauri v2 subtleties, documented in
§6): missing `core:window:allow-destroy` made close() silently no-op, and
physical-vs-logical size persistence made windows double each restart — now
divided by `scaleFactor()` and sanitized on load.

## 8. Cross-platform packaging

Both products are now set up to ship as separate installers for **macOS,
Windows, and Linux**:

- **Client (Tauri)**: `tauri.conf.json` targets `app/dmg` (macOS),
  `nsis` (Windows, per-user install), and `appimage`/`deb` (Linux). A real
  icon set was generated programmatically (chunky blood-red "K" on black,
  8-bit style) via `cargo tauri icon` — icns, ico, and all square sizes.
- **Server (kdxd)**: plain release binary packaged per-OS with
  `kdxd.example.toml` + the platform service file (`net.kdx.hotline.server.plist`
  launchd / `kdxd.service` systemd).
- **CI**: `.github/workflows/release.yml` — a 3-OS matrix (macos/windows/
  ubuntu) builds kdxd + the client bundle on each native runner, packages
  the server zip, and attaches everything to a GitHub Release on `v*` tags
  (or a manual run). Windows/Linux installers are produced there — each
  platform's installer must be built on that platform.

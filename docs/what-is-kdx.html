What is KDX?

+
−
Server greeting

Your community.
Your server.

Every online community exists somewhere. For most, that somewhere is a platform — Discord, Slack, Reddit, Facebook. The platform owns the place. It sets the rules. It logs the traffic. It can close the door.

KDX is a server you host yourself. Chat, file sharing, and controlled access — the core of a community space — running on your hardware, under your rules, with no third party in the middle.

The platform problem

You're renting someone else's space

Platforms survive by turning your community into an audience. Feeds surface what keeps people watching. Notifications arrive at the platform's discretion. Your history is theirs. When the platform changes its terms, folds, or decides your community is a liability, your place is gone.

What's missing

A server you actually control

The BBS era had this right. The sysop owned the box. The community was a list of people the sysop let in. No algorithm, no ads, no notifications the sysop didn't set. What was missing was modern security, easy deployment, and a client that doesn't feel like 1998. KDX is that.

What KDX Is

+
−

KDX is a client/server system for small private communities. You run a server daemon on a machine you control. People connect with the KDX client and get a chat window, a file browser, and a user list — the anatomy of a place, not a feed.

It's a Rust rebuild of Haxial KDX, a 2001-era server that ran underground music scenes, zine circles, and software crews through the late dial-up era. The design is proven. The implementation is modern: TLS 1.3, Argon2id password hashing, challenge-response authentication, SQLite persistence.

The server is a single binary. It generates its own TLS certificate on first run, opens one port, and starts listening. The client is a Tauri desktop app for macOS, Linux, and Windows. Trust-on-first-use certificate pinning so the client locks to your server and nobody can intercept the connection.

What You Can Do

+
−

Everything here is running against a real server you own. No feed, no algorithm, no notifications you didn't configure.

Chat

Public rooms + private messages

Live group chat with timestamps and a topic line set by any moderator. Private messages between users. All activity is scoped to the server — no cross-server indexing.

Every room has a topic. The sysop sets one; power users can too.
Files

Hierarchical file tree

Browse, upload, and download files organised in folders. Access is per-folder: a folder's class gate determines who can list and read it. Aliases let the same file appear in multiple places without duplicating bytes.

Alias mixtape-latest.flac → the actual file. The gate still applies.
Drop Boxes

Write-only submission vaults

A Drop folder accepts uploads from any class but lets no one list what's inside. The sysop sees the contents; contributors can't see each other's submissions. Anonymous review, no peeking.

Set up [DROP] submissions/ for demos, zines, or mixtapes.
Access Control

Four user classes, custom roles

Guest, User, Power User, Admin — each with a different access envelope. Custom roles layer on top. Assign them per-person, upgrade or downgrade at any time.

Move phraq from user → power user: one command in the admin panel.
Moderation

Kick and IP-level bans

Kick anyone from the current session. Ban an IP or CIDR range; the check runs before the TLS handshake completes, so a banned host gets a connection refused, not a login failure.

deny 5.5.5.0/24 — an entire range blocked at the network level.
Audit Log

Append-only admin history

Every admin action — role changes, topic sets, kicks, bans, newsgroup creation — is written to a persistent log. Admin-only, append-only. The receipts are always there.

Who banned who, when, and why. Logged and kept.
Channels

Multiple chat rooms (newsgroups)

Create named channels for different topics: #dev, #releases, #offtopic. Each has its own topic and history. Users join the ones they care about.

Spin up #dev for code and keep the lobby for social.
Auth

Challenge-response, no plaintext

Passwords never travel over the wire. The server sends a one-time challenge; the client responds with a keyed digest. Argon2id on the server side. Your password never leaves your machine.

Even if someone intercepts the handshake, they get a digest that expires immediately.
News

Server-side news board

Post persistent announcements that persist across sessions. New users see the latest bulletin when they connect. Good for rules, events, or anything that should outlast the chat scroll.

Post release notes, maintenance windows, or the house rules.

Who It's For

+
−

KDX is for communities where the people know each other — or at least know who invited them. It scales from two people sharing files to a few hundred regulars in a named space. It doesn't scale to public, anonymous, indexed, or algorithmic. That's not a limitation; that's the design.

The sysop is the person who runs it. They set the rules, control the door, and bear the costs: a server, some bandwidth, and the time it takes to know who's inside. If you're not willing to do that, a platform is the right choice.

If you are — if the value of a place that belongs entirely to your community is worth the overhead — KDX is built for you.

User class ladder
Admin / Sysop
Full access. Runs the server. Sets every rule.
Power User
Can set topics, moderate chat, manage lower users.
User
Full member. Reads everything they're allowed to see, uploads to drop boxes, chats.
Guest
Read-only or limited access. Useful for newcomers before you've decided to admit them fully.
Audience type

The sysop

Someone who wants to run a server for people they know. Could be a friend group, a creative collective, a small team. You want the place to be yours: your hardware, your rules, no third party making decisions about your community's future.

Audience type

Creative communities

Music scenes, zine circles, art collectives, writing groups. You have work to share, conversations to have, and a roster of people you've chosen to include. You want a file tree where your archives stay safe and a chat where the history is yours.

Audience type

Small teams with a trust relationship

Not every team collaboration belongs in a corporate chat app. If the people you work with are people you've chosen, and you don't need a vendor to manage your compliance, a server you control is a credible alternative.

Audience type

Communities tired of platforms

Your Discord server got banned, your Slack free tier expired, your subreddit was quarantined. You've been evicted before. You know what it costs to build something on rented infrastructure. KDX is what you run when you're done renting.

Not a fit: If you need discoverability, public indexing, anonymous users at scale, or push notifications to people who didn't install a client — KDX isn't designed for that. It's designed for the opposite.

Get Started

+
−

Run the server

$cargo install --git https://github.com/iamkhayyam/kdx-hotline kdxd

One binary. Generates its own TLS cert on first run. Opens one port. No configuration required to get started.

Get the client

$cargo install --git https://github.com/iamkhayyam/kdx-hotline kdx-client

Tauri desktop app: macOS, Linux, Windows. Connect to the server address. Trust-on-first-use certificate pinning locks the client to your server.

First-run checklist: start kdxd, note the address and port, open the client, enter the address, accept the certificate fingerprint, log in as sysop with the password you set during install. That's the whole setup.

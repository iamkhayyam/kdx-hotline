Background

Remember Hotline?

In the early 2000s, KDX was a peer-to-peer client for private file servers and IRC-style chat, speaking its own tight binary protocol over TCP. You connected to servers by hand, browsed their file trees, and talked to whoever was around. The interface was spare: black window, blood-red chrome, phosphor-green text.

This is a ground-up rebuild — same protocol energy, modern stack. Six Rust crates carry everything from the wire codec to the server daemon. The desktop client is a Tauri v2 app that renders the original aesthetic on a modern webview.

It is fully functional: 243 tests, cross-platform packaging via GitHub Actions, and a feature set that covers everything the original KDX did — plus TLS 1.3 and modern cryptography it never had.

What's inside

Full stack, no shortcuts

PKT
Wire Protocol
Custom 20-byte framed binary packets with typed message IDs. Full codec, fragmentation, and reassembly — all handwritten in kdx-protocol.
KEY
Secure Auth
Passwords stored as Argon2id hashes. Login is challenge-response: SHA-256(challenge ‖ verifier). The plaintext never crosses the wire.
#
Chat Rooms
Multi-room chat with flood protection, emotes, and broadcast messages. Per-room flags, kick and ban, server-wide admin broadcast.
FS
Virtual File Tree
Server-side file hierarchy with ACL-gated access. Drop boxes let users upload without read access. Alias nodes map one path to another without duplicating bytes.
XFR
Resumable Transfers
Chunked bidirectional transfers with a per-chunk progress bitmap. Interrupted downloads resume from the last confirmed chunk — no re-downloading from scratch.
REG
Tracker Registry
Public server directory. Servers announce themselves; clients query to discover available servers without knowing addresses in advance.

Run it yourself

Quick start

Server
# create an account (guest|user|power|admin)
cargo run -p kdxd -- useradd phraq s3cret power

# start the server (0.0.0.0:10700, self-signed cert)
cargo run -p kdxd

# or point at a config file
cargo run -p kdxd -- kdxd.toml
Client
# launch the desktop client
cargo run -p kdx-client
Build & test
cargo build --workspace
cargo test  --workspace  # no external services needed
Package (requires target OS)
cargo install tauri-cli --version '^2'
cargo tauri build
Code layout

Architecture

Seven packages in one Cargo workspace. Each layer depends only on the ones below it; the client app has no compile-time dependency on the server.

CrateKindResponsibility
kdx-protocol lib Wire format — 20-byte framed packets, codec, fragmentation, typed message IDs
kdx-crypto lib Argon2id password hashing and the challenge-response login handshake
kdx-storage lib SQLite persistence via sqlx — accounts, roles, file metadata, news, tracker entries
kdx-server-core lib Connection state machine, auth, chat rooms, virtual file tree, transfers, IP rules, audit log
kdx-client-core lib Async client library with zero UI deps — TOFU trust store, transfer engines
kdxd binary Server daemon — TLS listener, TOML config file, admin CLI sub-commands
kdx-client tauri app Desktop client — Rust shell + vanilla-JS webview; each feature in its own floating window
